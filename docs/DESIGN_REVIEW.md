# Design review guide

A design proposal is required for changes to the manifest, archive rules, public SDK contracts, CLI error categories, security boundary, or cross-language semantics.

Include the problem and non-goals; affected specification clauses, schema, fixtures, and implementations; compatibility impact; threat model; determinism and error behavior; and a test and migration plan.

Format changes require core review and implementation-owner review for each affected language. A merged design change must update `DECISION_LOG.md`, specification or roadmap, and conformance material as applicable.
