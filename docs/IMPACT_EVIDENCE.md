# Impact and adoption evidence

This is an evidence ledger, not a marketing claim. Update it only when a source can be linked or reproduced.

## Verified today

- ReproPack defines a language-neutral evidence-bundle contract with a JSON schema and canonical fixtures.
- Rust, TypeScript, and Python implementations are maintained in independent repositories.
- The implementations pass the shared semantic fixtures and the coordinated interoperability matrix.
- Core hosted CI validates documentation, Rust checks, and interoperability on Ubuntu and Windows.
- v0.1.1 GitHub Releases provide checksum-verified Core, TypeScript, and Python artifacts.
- The documented security boundary forbids implicit execution and environment reconstruction; redaction detection remains advisory.

## Not yet established

- Independent downstream projects consuming ReproPack.
- Production or public CI deployments.
- External testimonials, citations, or case studies.
- Contributions from maintainers outside the core project team.
- Registry download or adoption metrics.

## How to add evidence responsibly

For each external adoption record, add the project name, public URL, date, version, integration surface, and a short description of the measurable problem addressed. Do not publish private customer information, credentials, unverifiable usage counts, or claims that a test fixture proves production impact.

The next credible evidence milestone is one independently documented integration or pilot, followed by a reproducible example and maintainer permission to name the project publicly.
